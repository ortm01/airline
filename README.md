# Airline Passenger Satisfaction: бинарная классификация

Учебный ML-проект: предсказание удовлетворённости пассажиров авиакомпании (`satisfied` / `neutral or dissatisfied`) по оценкам сервиса и данным о поездке. Сравниваются пять моделей, гиперпараметры подбираются в Optuna с кросс-валидацией.

## Данные

- Около 100 тысяч строк, 24 столбца после предобработки.
- Таргет: `satisfied_1` (1 — пассажир доволен), классы сбалансированы (около 50/50).
- Признаки:
  - оценки сервиса по шкале 0-5 (`inflight_wifi`, `online_boarding`, `seat_comfort`, `cleanliness` и др.);
  - числовые (`age`, `flight_distance`, `departure_delay`, `arrival_delay`);
  - one-hot (`gender_Male`, `type_of_travel_Personal Travel`) и порядковый код класса обслуживания (`travel_class_code`).
- Служебные столбцы `idx` и `id` и сам таргет в признаки не попадают.
- Пропусков в данных нет.

## Модели

| Ключ | Модель |
|---|---|
| `lr` | Logistic Regression (в `Pipeline` со `StandardScaler`) |
| `rf` | Random Forest |
| `xgb` | XGBoost |
| `lgb` | LightGBM |
| `cat` | CatBoost |

## Методика

1. **Разбиение:** 80% — обучение и подбор (`x_tmp`), 20% — тест (`x_test`), со стратификацией по таргету. Тест используется один раз в конце.
2. **Подбор гиперпараметров:** Optuna (`TPESampler`), отдельный study на каждую модель. Функция `unic(trial, model_name)` описывает пространство поиска, а `make_cv(name)` возвращает целевую функцию.
3. **Кросс-валидация:** `StratifiedKFold` на 3 фолда внутри каждого trial; целевая метрика — средний ROC-AUC по фолдам.
4. **Бустинги:** число деревьев задано потолком (2000), реальное число определяет early stopping на валидационном фолде. Для финальной модели берётся среднее найденное число деревьев ×1.1.
5. **Финальная модель:** параметры лучшего trial (`unic(FixedTrial(best.params), name)`), обучение на всех данных без теста, оценка на тесте.

## Результаты

Метрики на отложенной тестовой выборке (прогон с исходными диапазонами поиска):

| Модель | CV AUC | Test AUC | Test accuracy | Test logloss |
|---|---|---|---|---|
| LightGBM | 0.99298 | 0.99410 | 0.96046 | 0.09545 |
| CatBoost | 0.99275 | 0.99401 | 0.95927 | 0.09708 |
| XGBoost | 0.99228 | 0.99384 | 0.95785 | 0.09802 |
| Random Forest | 0.98963 | 0.99153 | 0.95119 | 0.11917 |
| Logistic Regression | 0.91417 | 0.91593 | 0.85706 | 0.36470 |

Что можно сказать по результатам:

- Три бустинга практически неразличимы по качеству (разница порядка 0.0003 по AUC), логистическая регрессия заметно слабее: ей не хватает нелинейностей и взаимодействий признаков.
- Test AUC немного выше CV AUC, потому что финальные модели обучались на большем объёме данных, чем в фолдах.
- Разброс AUC по фолдам около 0.0001, то есть оценки стабильны.

> **Примечание.** После этого прогона диапазоны поиска были изменены. Повторный подбор с обновлёнными диапазонами был завершён только для `lr`, `xgb` и `lgb` (CV AUC: 0.91431, 0.99307, 0.99344); для `cat` и `rf` он не был доведён до конца из-за времени, поэтому таблица выше относится к более раннему прогону.

## Важность признаков

Для LightGBM оценивалась важность по gain, permutation importance на тесте и SHAP. Наибольший вклад вносят `inflight_wifi`, `online_boarding` и `type_of_travel_Personal Travel`, остальные признаки заметно слабее.

## Ограничения

- Датасет очень «лёгкий» для бустингов: AUC около 0.994 и минимальная разница между моделями. Дальнейший тюнинг гиперпараметров даёт прирост порядка шума между фолдами.
- Число trials небольшое (15-30 на модель) из-за времени обучения, поэтому часть лучших параметров найдена на случайной стадии поиска.
- Ансамбли (усреднение, стекинг) не проверялись: три бустинга слишком похожи, прироста от них ожидать не стоит.
- Возможная утечка данных полностью не исключена и требует отдельной проверки.
